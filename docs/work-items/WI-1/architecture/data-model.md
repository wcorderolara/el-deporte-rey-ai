# WI-1 Data Model

- Author: architect (task WI-1-T09). Date: 2026-10-27. Part of the full-mode architecture (`architecture.md`). Decision: AD-05 (SQLite through `node:sqlite`), AD-13 (approval bound to versions), AD-19 (data directory, no deletion).
- Bounds: R-100 and R-109 (local, no hosted infrastructure), R-043 and R-044 (history and traceability), R-112 and R-113 (no player-level and no user-account data; R-233), OD-08 (no deletion function).

## 1. Storage layout

| Store | Location | Content |
|-------|----------|---------|
| Database | `<dataDir>/edr.sqlite` (WAL mode, `foreign_keys=ON`) | every record below |
| Rendered slides | `<dataDir>/renders/<projectId>/<elementVersionId>.png` | PNG per slide version; SHA-256 stored in `element_versions` |
| Exports | `<dataDir>/exports/<projectId>/<exportId>/` | `01.png` ... `NN.png`, `caption.txt`, `manifest.json`; hashes in `export_files` |
| Brand assets | `<dataDir>/brand-assets/<assetId>.<png or jpg>` | operator-registered brand files; SHA-256 in `brand_assets` |

`<dataDir>` defaults to `data/` in the repository root (git-ignored) or `EDR_DATA_DIR`. Every file path stored in the database is relative to `<dataDir>` and built from generated IDs only.

## 2. Conventions

- Tables are SQLite `STRICT` tables. IDs are `TEXT` UUIDs generated by `crypto.randomUUID()`. Times are `TEXT` ISO-8601 UTC with milliseconds (`2026-10-27T16:32:21.123Z`). JSON columns are `TEXT` validated by Zod on write and read, with `CHECK (json_valid(col))`.
- Enumerations are `TEXT` with `CHECK (col IN (...))`.
- Rows are never deleted (OD-08). Superseded or invalidated rows carry a timestamp column instead.
- Migrations: `apps/server/migrations/NNNN_<name>.sql`, applied in order in one transaction each by the migration runner at startup, recorded in `schema_migrations`. The full MVP schema is migration `0001_initial.sql`, created by T18 (owner of `apps/server/migrations/**` and `apps/server/src/platform/db/**`; T10-F21). A later schema change is a new migration and a decision above LOW (schema change).
- SQL access (T10-F14): the `Db` port exposes prepared statements with bound parameters only; dynamic identifiers (column or sort names) come from code constants, never from input; a lint rule rejects template literals containing `${` passed to `prepare` or `exec`.
- Guard atomicity (T10-F15): every approval, final-approval and export guard check and the write it protects run in one synchronous `BEGIN IMMEDIATE` transaction on `DatabaseSync`, with no `await` inside.
- Failure reasons (T10-F10): `failure` columns hold a JSON object `{ code, sourceId, path, httpStatus }` with `code` from the closed list of the contract schema `Failure`; never a provider body, an exception message or a file path.
- Files (T10-F13): the data directory is created with mode 0700; new files are created with the exclusive flag (`wx`), never overwritten; IDs are checked against the UUID pattern before any path is built (also when read back from the database); containment is checked against `fs.realpath(dataDir)`.
- Catalog data (competitions, seasons, matchdays), templates and languages live in configuration and code, not in tables; rows reference them by ID.

## 4. Indexes

`workflow_runs (project_id, status)`, `stage_runs (run_id)`, `observations (run_id, fact_key)`, `facts (run_id, status)`, `fact_evidence (observation_id)`, `content_drafts (project_id, superseded_at)`, `elements (carousel_id)`, `element_versions (element_id, superseded_at)`, `element_fact_refs (fact_id)`, `approvals (element_version_id, at)`, `final_approvals (carousel_id, invalidated_at)`, `exports (carousel_id)`, `brand_assets (kind, active)`.

## 5. Excluded data (R-112, R-113, R-233)

- No table, column or JSON field holds player-level information (player names, goal scorers, line-ups, cards, player statistics). Provider schemas are allow-lists (`contracts/provider-ports.md` section 1); unknown fields are dropped before persistence.
- No user, account, credential, session or operator-identity entity exists. No personal data of the operator is stored.
- No secret is stored (`workflow_runs.config_snapshot` holds adapter IDs and options without credentials).
- T18 adds an automated schema test that lists every table and column through `sqlite_master` and `pragma_table_info` and fails on any name matching `player|scorer|lineup|line_up|user|account|password|session|email|login` (R-233), and T45 confirms it in the conformance review.

## 6. Traceability chain (R-044, R-221)

`exports -> export_files (element_version_id) -> element_versions -> element_fact_refs -> facts -> fact_evidence -> observations -> sources`, plus `disputes` for disputed or resolved facts and `workflow_runs.config_snapshot` for the source configuration in force. The export `manifest.json` repeats the element version IDs and fact IDs per file, so that an exported folder can be traced back even when opened outside the application.

## 7. Retention

Everything is kept locally without expiry; there is no deletion function (OD-08). Superseded drafts, versions and invalidated final approvals remain readable for history (R-043, R-220).
